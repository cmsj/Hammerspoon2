    Class HSSocket

    A TCP or Unix domain stream socket, created by hs.socket.create(). A socket can either connect to a server (connect()/connectUnix()) or listen for incoming connections (listen()/listenUnix()). Each connection a listening socket accepts is handed to its callback as a new HSSocket, which inherits the listening socket's callback. Reading is request-driven: queue a read with readUntil(), readBytes() or readAvailable(), and the callback receives a "data" event once that read can be satisfied. Data that arrives before you ask for it is buffered. Reads can be queued before the socket connects, and each one carries an optional numeric tag that is passed back to the callback, so a single callback can tell a protocol's reads apart (e.g. a header and a body). Received data is delivered as a Uint8Array. Use hs.socket.decodeText() to turn it into a string. Do not instantiate HSSocket directly - use hs.socket.create().

    readTimeout

    readTimeout: number

    How long, in seconds, a queued read may wait with no data arriving. The timer runs only while a read is queued, and restarts whenever data arrives, so a slow but steady transfer doesn't time out, and nor does a connection that's quiet while no read is queued. When it expires, the callback receives an "error" event and the socket disconnects. 0 (or any negative number) means no timeout. Defaults to hs.socket.readTimeout.

    Remarks

    Protocols where the peer can stay quiet for a long time while a read is queued (e.g. waiting for the next line of a notification stream) usually want no read timeout

    listen

    • listen(port: number, address?: string | null): HSSocket

      Listens for incoming TCP connections. The callback receives "listening" once the socket is ready, then "connection" for each client that connects. By default the socket listens on all network interfaces. Pass one of this Mac's IP addresses to accept connections only on that address (and so only on the interface that has it), e.g. "127.0.0.1" to accept connections only from this Mac. Use hs.network.addresses() to find an interface's addresses. If the interface's address can change (e.g. it comes from DHCP), watch State:/Network/Interface/<name>/IPv4 with hs.network.configurationWatcher() and listen again when it does.

      Parameters

      • port: number

        The TCP port to listen on, or 0 to let the system choose one (see localPort).

      • Optionaladdress: string | null

        A local IPv4 or IPv6 address to listen on. Defaults to all addresses.

      Returns HSSocket

      The socket, for chaining.

      Remarks

      A listening socket, and its callback, stay alive until it stops listening, even if you don't keep a reference to it

Queue a read on it to start receiving. read's tag. connection, a "disconnected" event follows. reason, including calling disconnect(). Data received that no read had asked for yet is discarded. An "error" event on its own never changes the socket's state: errors such as calling connect() on a socket that is already connecting, or writing to an idle socket, leave it as it was. Every connection that ends, and every listening socket that stops, gets a "disconnected" event, after the "error" that caused it, if any. So reconnecting belongs in the "disconnected" handler, not the "error" one. When the peer closes the connection, data already received for the first queued read is delivered to it in a last "data" event, before "disconnected", even though the read isn't satisfied: it may be missing its delimiter, or be shorter than asked for. This is how to receive the end of a stream that the peer ends by closing, such as an HTTP/1.0 response body.
