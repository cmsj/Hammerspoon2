hs.spoons

Module

Load, install and update Spoons - packaged, reusable pieces of configuration.

Spoons live in the Spoons directory inside your config directory. Every Spoon you load is also available on hs.spoons under its name, so hs.spoons.load("Greeter") makes hs.spoons.Greeter available to the rest of your config. That's why a Spoon can't be named after one of this module's own methods or properties.

Spoons can be installed from any GitHub repository ("owner/repo"), or from a zip file at any https:// URL. There's no central list of Spoons: you choose where each one comes from, so only install Spoons from sources you trust. Pin the version you install with ref (a GitHub tag or commit) or sha256 (for a zip URL), and nothing changes until you choose to.

Quick start

// Installs Greeter the first time this runs, then loads it, configures it and starts it
hs.spoons.use("Greeter", {
    source: "jane/hs2-spoons",
    ref: "v1.2.0",
    config: { message: "Time for a break!" },
    start: true
})

hs.spoons.load(name) -> Object

Load an installed Spoon by name. A Spoon must contain a well-formed `spoon.json` (with non-empty `name`, `author`, `version`, and `description` fields) and an `init.js`, or loading fails with an exception. `init.js` is loaded through the same `require()` used for the rest of your config, so it can itself `require()` further files from within the Spoon's own directory using relative paths. On success, the Spoon is also stored on `hs.spoons` under its name, so other code can reach it without loading it again. `init.js` must set `module.exports` to an object (or a function, since functions are objects too) - loading fails with an exception otherwise. Its `author`, `description`, and `version` properties are then set from `spoon.json`, overwriting any of the same name the Spoon's own `init.js` set, so that information is always present and always reflects what's on disk. If the resulting object has an `init()` method, it's called automatically (with `this` bound to the object) before `load()` returns - matching Hammerspoon 1's behavior. An exception thrown from `init()` fails the load: nothing is stored on `hs.spoons`, and `load()` throws. Unlike `init.js` itself (which `require()` only ever evaluates once), `init()` runs again on every `load()` call for the same Spoon, since the same cached object is returned each time - write it to be safe to call more than once, or do one-time setup at `init.js`'s top level instead. The exception's `code` is `ENOTINSTALLED` if there's no such Spoon, `EINVALIDARG` if the name can't be a Spoon's, or `EINVALIDSPOON` if the Spoon is malformed. An exception thrown by the Spoon's own code is passed on as it is.

hs.spoons.install(name, options) -> Promise<{name: string, version: string, author: string, description: string, source: string, ref: string | null, commit: string | null}>

Download a Spoon and install it into the `Spoons` directory. It isn't loaded: call `hs.spoons.load()` (or use `hs.spoons.use()`, which does both) once it's installed. The source is downloaded as a zip file. Its Spoons are every `*.spoon2` directory at its top level or in a `Spoons` directory, or, if there are none, the whole archive, if it's a single Spoon. An archive that holds a single directory, as a repository's does, is looked inside. The Promise rejects with an `Error` whose `code` says what went wrong: `EINVALIDARG`, `ENOTFOUND` (no such repository, ref, URL, or Spoon in the archive), `ENETWORK`, `EINTEGRITY` (the download didn't match `sha256`), `EINVALIDSPOON`, `EEXISTS`, or `EIO` (for anything else, such as failing to write the Spoon to disk).

hs.spoons.update(name) -> Promise<boolean>

Update an installed Spoon: download it again from where it was installed from (the same source, ref and URL), and reinstall it if its version has changed. A Spoon installed from a pinned tag, commit or versioned URL doesn't change; install the newer one with `install(name, { ..., force: true })` instead. Besides the codes `install()` uses, the Promise rejects with `ENOTINSTALLED`, `ENOSOURCE` for a Spoon that wasn't installed by `install()` (or was since replaced some other way, such as by opening a `.spoon2` file), or `ECANCELED` if the Spoon was reinstalled while the update was downloading.
Declaration
hs.spoons.update(name) -> Promise<boolean>
Parameters

Returns

Resolves with true if the Spoon was updated, or false if it was already up to date

    hs.spoons.update(spoon.name)
        .then(updated => { if (updated) console.log(`Updated ${spoon.name}`) })
        .catch(err => console.error(`${spoon.name}: ${err.message}`))
}
